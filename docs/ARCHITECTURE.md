# One shared policy connects three client adapters

> **2026-10-21** · Aster · `current`
>
> Devarness makes Claude Code the primary harness. It combines existing
> capabilities through a common policy and measured verification, while
> keeping each client's authentication and runtime independent. This is an
> integration, not a claim of authorship over upstream systems.

## The shared core owns process and safety

The router, Library catalogue, local skills and deterministic checkers
form the core. Startup verifies the current checkout. Claude Code uses
local hooks, Codex reads AGENTS.md and shared skills, and Pi adds its
local discovery extension. Provider credentials never cross adapters.

## Harness² contributes a method that is tested through harness-step

Freeze a representative task and budget, run a reference, propose
process and domain candidates, probe the same task, compose supported
changes and retain a dated step record. Native CLI probe execution
requires separate client installation and authentication; no paid probe
runs in bootstrap or CI. The upstream repository stays pinned.

## Optional integrations cannot silently change the core

Notifications, dashboard bridges, scheduled updates, MCP servers,
research tools, reverse tools and simulation runtimes are optional.
The source is available without implying an installed integration.
User configuration uses the Devarness namespace. No global launchers,
credentials or private manifests are inherited from another checkout.
