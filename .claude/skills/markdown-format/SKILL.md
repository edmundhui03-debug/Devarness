# House documents

Every Markdown file in this workspace follows one format, so the owner can open
any of them and know within three lines what it says and whether it still
applies. That is a house rule, not a per-request preference.

Paths are relative to this Devarness checkout. From its root, run
`python3 Harness/bin/<tool>` to select this checkout explicitly.

## The four steps

```bash
cp Harness/templates/markdown-doc.md mydoc.md   # the template is a worked example
# ...write it...
python3 Harness/bin/md-format toc mydoc.md    # only above 150 lines
python3 Harness/bin/md-format check mydoc.md  # must exit 0
```

`md-format check` with no argument checks every tracked `.md` in dev. `md-format
status` prints every marked section across the workspace, grouped by state —
that is the map the owner reads to find what is still open. `md-format fix`
repairs trailing whitespace and the final newline, nothing else; it will never
rewrap your prose and never touches a line inside a fence, because those bytes
may be a fixture or a tab-separated field. `md-format selftest` runs fixtures
covering every rule, fired and not fired. Run it after changing
`Harness/bin/md-format`; each case is a defect found during the build, so a
failure means one has come back.

`md-format rewrap FILE` reflows plain prose paragraphs to 80 columns. It leaves
fenced code, tables, links and front matter alone. Use this command to avoid
rewrapping YAML fields or code whose whitespace carries meaning.

`md-format dupes` reports a normative sentence stated in more than one document,
which the router forbids: "the copy outside this file is the one that drifts".
It skips parallel `AGENTS.md` and `README.md` notes, whose shared boilerplate
is the point of them, and groups a document with its own revisions, so V5
agreeing with V6 is one document rather than two.

## The format

**The title is a sentence.** It says what the document concludes. `# Rev0 as a
reference — what it confirms, and what it catches`, not `# Rev0 notes`. One H1
per file, first content line.

**The header block comes next**, a blockquote, always the same shape:

```markdown
> **2026-09-11** · Peter · `current`
>
> Two to four sentences saying what this concludes. Someone who reads only
> this should have the answer and know whether it still holds.
```

Document status is `current`, `draft`, `superseded` or `historical`. It answers
the question that makes an old document dangerous: is this still true?

**Headings state a claim.** "The 0.2 mm vias are a regression" earns its place;
"Findings" does not. Headings are what a skimming reader actually reads, so make
each one carry its section's conclusion. Never skip a level.

**A section with a state says so on its first line**, before any prose:

```markdown
## J1 and J2 order the wrong connector variant

`open` · blocks the order · needs an enclosure decision (`TASK.md:22`)
```

Use `open`, `fixed`, `blocked`, `partial` or `needs-owner` — the same five words
everywhere, so `md-format status` can gather them and a grep can find them. Omit
the line entirely on a section that is just context.

**Cite what you checked.** Any claim about this repository names
`path/to/file:line`. It is clickable in Claude Code and greppable everywhere
else, and it is the difference between a report and an assertion.

**Wrap prose at 80 columns.** Tables, code blocks and links are exempt. The
checker measures the text, not the `>` or `-` in front of it.

**One alert per document, at most.** `> [!WARNING]` is for the single thing that
blocks. Three of them and the reader stops seeing any.

**Contents above 150 lines**, generated by `md-format toc` so it cannot go
stale. It lands immediately before the first section, below all the header
material.

**Say what you could not establish.** A document listing only what worked is not
evidence. The next agent needs to know where your edge was.

## What the rule does not touch

`md-format` skips what is not ours to reformat and says how many it skipped:
vendored clones and the skills symlinked out of them, installed packs under
`.agents/`, `md-pages` output in `datasheets/extracted/`, and KiCad's
`.history/`. **Never reformat a vendored clone** — `Harness/CLAUDE.md` forbids
it and an upstream `git pull` would undo it anyway.

`SKILL.md` files keep upstream's YAML front matter as their contract, so the
header block rule is waived for them. The prose, width, table and link rules
still apply. Files that open with front matter or an HTML comment keep it; the
title is expected after it, not before.

## Rules that matter

**Markdown here is not bilingual.** The English/Cantonese house rule is for HTML
deliverables — `bilingual-page` owns that. Markdown carries working evidence
for the project; translation is a separate project choice.

**Use portable Markdown links.** Ordinary relative links work in terminals,
GitHub and the owner's navigation apps. Obsidian wikilinks are not portable
to GitHub; use ordinary links, which the checker verifies resolve. Application
installation state belongs to Setup records, not this formatting rule.

**Retrofit nothing in bulk.** The rule binds new files and files you are already
editing. `md-format check` reports the backlog on everything else so the owner
can choose; rewriting a finished record to satisfy a format risks changing
evidence, which is worse than an unformatted document.

**Every client follows the same rule.** `AGENTS.md` and the root `CLAUDE.md`
share this requirement so it applies across the supported clients.
