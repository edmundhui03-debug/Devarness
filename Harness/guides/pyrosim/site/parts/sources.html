Sources and review

What was checked, what was run, and what is still unverified

Nothing in this guide was written from memory. Menu paths and defaults come from Thunderhead's own 2026.1 documentation and from the strings inside the shipped software; physics and keywords come from NIST's FDS 6.10.1 User's Guide by page; the room and its burner come from ISO 9705; the numbers come from simulations that were actually run on this machine.

What this guide could not establish

  • No screenshot in this guide was taken from PyroSim. PyroSim runs only on Windows and this guide was written on a Mac, so every screenshot slot is marked for you to fill from the office desktop.
  • The guide targets PyroSim 2026.1. If your copy is 2026.2, the solver is identical but a few menu labels differ; where that is known, the text says so.
  • A handful of interface details could not be confirmed without the software on screen: which ramp-up options the burner dialog actually lists, whether auto-save before running is ticked on a fresh install, and the exact install path on your machine.
  • ISO 9705-1:2016 Annex B, which fixes where the standard's own instruments go, is not public. The sensor positions in the reference case are this guide's choices, made to match what DATASET needs.
  • The reference run is coarse and reads cooler than measurements of a real ISO room. It is a check on your method, not a statement about fire.

Corrections made during writingfixed The doorway flow devices were rewritten to the documented MASS FLUX X form, because MASS FLOW was removed from the FDS documentation in 6.7.8 and survives only for backward compatibility. The room's lining was changed to aerated concrete with properties cited from NUREG-1805, replacing values that had no source. The Day 6 exercise's third fault stopped being a fault when the model gained its second mesh, and was moved above the ceiling and re-run.
The biggest thing Aster caughtfixed FDS averages device output over each output interval unless told not to, so the Day 7 pipeline was decimating values that had already been averaged — which is exactly what the DATASET contract decimates in order to avoid. The template now sets TEMPORAL_STATISTIC='INSTANT VALUE' on every training channel, verified in a re-run's .out file. The reference numbers in this guide predate that change and are one-second means.
